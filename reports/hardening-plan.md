1. **Один коммит артефактов ДЗ** (без фанатизма веток): `REPORT.md`, `reports/`, `.cursor/`, `workflows/worktree-isolation.md`, правки `workflows/ui-check.md` и конфигов линтера. Затем пуш `main`.
2. **Журнал живой:** после каждой содержательной сессии дописывать блок в `reports/sessions.md` по шаблону в шапке файла.
3. **Worktree по делу:** следующую рискованную правку вести в `D:/Programming/invoice-constructor-wt-isolation` (ветка `hw2-isolation`) через GitLens MCP, не в основном checkout. Основной каталог остаётся на `main`.

Критерий: проверяющий видит в git отчёт, журнал, workflow, скиллы, хуки и сценарий изоляции.

## P1 — агент делает то, что обещали хуки

1. **Хук тестов на реальный UI.** Сейчас `check-ui-tests.cjs` смотрит только `src/features/**/ui`. В проекте UI в `src/pages/constructor/ui`. Расширить фильтр на `src/{pages,features,widgets,entities}/**/ui/*.tsx`, не ломая исходный контракт про features.
2. **Хуки tsc и стилей** (сессия 5 в журнале оборвалась). На рабочие события Cursor:
   - после правок `src/**/*.{ts,tsx}` — `npm run ts-check` (или узкий `tsc`);
   - после правок CSS — `npm run lint:styles`.
     Пути `src/components/**` в задании не существуют — матчить фактические CSS Modules. Не блокировать агента на первом прогоне, пока не проверен payload хука.
3. **Напоминание про журнал:** `sessionStart` → короткий `additional_context` со ссылкой на `reports/sessions.md` (fail-open).

Критерий: правка карточки/формы даёт напоминание про тест; tsc/stylelint реально бегут; новая сессия знает, куда писать журнал.

## P2 — качество продукта

1. **Vitest + RTL** по скиллу QA: форма (валидация, дабл-сабмит / `requestKey`), статусы, фильтр списка, `PayView`. Мок `localStorage`. Скрипт `npm test`.
2. **FSD без фанатизма:** вынести инвойс в `entities/invoice` (types, repository, status, validate, format), страницу оставить композицией. Слайсы с одной ссылкой не плодить. Cross-imports на entities разрешены. Прогон `npm run lint:fsd`.
3. **Performance-скилл по факту, не только файлом:** таймер раз в секунду в `ConstructorPage` обновляет весь список — проверить, не гоняет ли лишний ререндер карточек; `useCallback` только если дети в `memo`. Формат ответа: Проблема / Причина / Решение.

Критерий: `npm test` и `npm run lint` зелёные; steiger не орёт; UI-check после рефакторинга повторён.

## P3 — плюсы ДЗ

1. Playwright в репозитории (`npm run test:e2e`), те же сценарии, что в `workflows/ui-check.md`; Vite слушает `127.0.0.1`, не только IPv6.
2. Workflow «агент-ломатель»: отдельный агент пытается сломать форму/оплату по чеклисту отказов, пишет `reports/breaker.md`.
3. Инъекции: узкий `beforeSubmitPrompt` или правило — не коммитить секреты, не ходить git-командами в обход GitLens MCP, если правило проекта это требует.
4. GitKraken-логин в MCP — только если нужны PR/issues из ДЗ. Для локального git и worktree не обязателен.

Критерий: плюсы видны отдельными файлами и одним прогоном, не смешаны с P0.
